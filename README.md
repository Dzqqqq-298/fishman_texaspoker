# 鱼人德州 · Fishman Poker

朋友专用的德州扑克：登录进入大厅，创建好友房、设置规则和时长，再入座开赛。同时最多存在一个房间，结束结算后可以创建下一场。手机竖屏、电脑宽屏，入座后每个玩家位于自己视角的下方中央。

## 本地启动

需要 Node.js 22.13+（使用 Node 内置 SQLite）和 npm。

```sh
npm ci
npm run setup
npm run dev
```

打开 **http://localhost:9527**。初始账号是 `admin`，随机密码保存在被 Git 忽略的 `.env.local` 的 `ADMIN_PASSWORD` 中。只有空数据库首次启动时会创建管理员；之后修改该环境变量不会改变已有密码。

手机和电脑接入同一个 Wi-Fi，用启动输出中的 `http://局域网IP:9527` 打开。若无法访问，检查 Wi-Fi 客户端隔离，以及 Windows 防火墙是否允许 Node 在私人网络接收连接。开发服务不是公网部署入口。

管理员登录后可在大厅「创建朋友账号」中分发账号。每个账号使用不同浏览器/设备登录；同一账号的新登录会令旧登录失效。

任一已登录玩家可以创建当前唯一房间，并成为房主。创建房间和进入房间不扣积分，带入入座才扣除。至少两人就绪后，由房主点击「开始比赛」。浏览大厅不会自动离座。

在牌桌点击任一空座，确认带入金额后入座。空座按房间人数固定排列，入座后本人视角转至下方中央；其他人入座或离座不改变座号。设置与记录默认收起，点击右上方按钮展开抽屉；积分与时间卡在「我的」查看。

已入座时，在手间点击空座可换座，桌上筹码保留。开赛后新加入或换座可选择“等大盲 / 补盲入局”，欠盲按本场账号记录；牌桌显示等待状态，可随时切换入局方式。Straddle 提前预约下一手，换座后重新按新顺序接力。

## 已实现的首版范围

- 密码哈希、HttpOnly 会话 Cookie、关闭公开注册、管理员创建账号。
- 大厅、创建房间、2～11 人桌、房主手动开赛；服务端保证同时只有一个房间。
- 建房设置名称、人数上限、盲注、带入范围、比赛时长、Straddle、鱿鱼、是否允许追加和中途加入。开赛前可编辑，开赛后锁定。
- 首次成功开赛才计时；暂停和服务离线期间仍计时。到时或房主手动结束，打完本手后结算、退回筹码、关闭房间并保存战绩；大厅展示最近 5 场。
- 开赛后自动下一手；房主可设置本手结束后暂停，或手动继续。
- 默认 10/20 盲注，2,000 带入，可自定义、多次追加；仅在手间生效。
- 服务端洗牌、四轮下注、最小加注、短全下重开判断、主池与边池、平局分池。
- 本手提前预约下一手 Straddle，按顺位依次确认 2BB→4BB→8BB，可设最高 16BB；每手预约独立，换座与入局顺序变化后重新确认。
- 等待自然大盲、补欠盲、手间换座；补大盲抵跟注，补小盲进入主池，本场欠盲跨离桌/重连保留。
- 25 秒行动时间，手动预备时间卡，每张 30 秒、每次行动最多一张；每天 3 张，获发底牌每 20 手补一张，上限 3 张。
- 简单鱿鱼：3 人以上、独赢主池得标记、每人最多一枚，钱包预留最大责任积分，正常/提前结算。
- 北京时间 04:00 手间每日重置到 100,000；先结算鱿鱼与旧筹码、关闭当前房间，保留战绩与流水。
- 断线重连、动作去重、版本校验、SQLite 事务持久化；服务器重启恢复原牌局并等待房主继续。
- 用户只能收到自己的底牌和已公开的摊牌信息。普通比牌按顺序自动亮牌/盖牌；结束后可点击底牌补秀一张或两张，未公开底牌不写入牌谱。
- 两人 All-in 且下注结束后协商发一/两次，三人及以上只发一次。双发独立分池，未达成一致默认发一次。
- 收起式加注面板、金额滑杆、底池比例快捷下注、倒计时环、提示音、下注金额与筹码结算动画。
- 房间文字聊天，本手 All-in 的玩家本手结束前禁言；服务端限制发送频率。
- 整场结束自动显示结算页，支持最后一手补秀与本场牌谱；大厅历史战绩也可查看牌谱。

牌局采用虚拟积分和固定盲注，可重复带入；这里的「比赛」是一场计时好友局，没有淘汰晋级或自动升盲。详细约定与边界见 [docs/RULES.md](docs/RULES.md)，大厅设计参考见 [docs/ROOM_FLOW.md](docs/ROOM_FLOW.md)。

## 当前限制与后续工作

- 这是可进行本地联机验证的首版，不代表已在手机真机完成验收。按项目要求未进行截图或视觉巡检。
- 短期离桌重入强制带回原筹码、线下买庄位规则尚未实现；目前用等待/补盲处理本场重入和换座。
- 账号停用、修改/重置密码、逐动作动画回放和日榜尚未实现；已有公开牌谱和下注过程记录。
- 鱿鱼参与者离线、暂离或筹码为零时，下一手暂停；房主需等待其恢复、补码或提前结算。
- 数据库保存恢复牌局所需的牌堆，服务器管理员具有读盘权限，不提供可验证的去信任发牌。
- Docker 部署配置已提供；本机未执行 Linux 容器构建、云服务器部署、备份恢复或真实公网 HTTPS 验证。

测试包括牌型、2～11 人筹码守恒、边池、Straddle、短全下、时间卡、鱿鱼、跨日重置、恢复、唯一房间限制、规则校验、时长到期、手动结束和重复结算保护，以及真实 HTTP + 11 个 WebSocket 客户端建房、对局、结算、再建房。网络测试使用临时数据库与随机空闲端口，不修改开发账户。

## 腾讯云部署

目标：Ubuntu Server 24.04 LTS，4 核/4GB/40GB。首先安装 Docker Engine 与 Compose 插件，域名 A 记录指向服务器公网 IP，腾讯云轻量防火墙放行 80/443。应用 9527 仅在容器内部开放。

在项目根目录创建独立的、被 Git 忽略的 `.env.production`：

```dotenv
DOMAIN=poker.example.com
ADMIN_USERNAME=admin
ADMIN_PASSWORD=替换为至少12位的独立强密码
```

```sh
docker compose --env-file .env.production -f deploy/compose.yaml up -d --build
```

部署环境使用独立数据库和管理员密码，本地测试账户不会自动上传。Caddy 根据域名申请 HTTPS 证书。系统升级或停止应用前先结束比赛并完成结算；服务意外退出后恢复同一牌局，默认等待房主继续。房间总计时不会因服务重启而重置。

从原来的固定牌桌版本升级时，已有筹码和进行中的手牌保留，并迁移为「原有好友房」。该房间不限时，战绩从升级时开始计算；房主可结束后按新流程创建房间。

数据位于 `poker-data` 命名卷，更新容器不删除数据。不要运行带 `-v` 的 `docker compose down`。备份应使用 SQLite backup API 或暂停服务后备份整个数据卷，不要只复制正在写入的 `.sqlite` 主文件。生产备份任务和保留策略需在实际服务器接入时配置。
